# Методика анализа данных DataStory AI

Методика загружается главным LLM-воркфлоу (LangGraph) на этапах `build_analysis_plan` и `generate_insights`.
Правила ниже проверяются кодом (`validate_analysis_plan`, `verify_insights`): нарушение отклоняется, а не публикуется.

## Когда применять

Применяй методику, если нужно:
- составить план анализа подтверждённого датасета: какие показатели считать и какие графики строить;
- выбрать тип визуализации для показателя;
- написать аналитический вывод по результату расчёта;
- проверить, что вывод опирается на числа, а не на догадки.

Не применяй методику:
- для загрузки, очистки и приведения типов данных — это делает профилировщик;
- для арифметики — все расчёты выполняет MCP-сервер;
- для прогнозов и поиска причин изменений — в MVP они не поддерживаются.

## Последовательность анализа

### Шаг 1. Проверка структуры данных
Опирайся только на сводку датасета (`profile_dataset`): названия колонок, типы, число уникальных значений, пропуски. Колонки, которых нет в сводке, не существуют. Колонки с персональными данными недоступны для анализа.

### Шаг 2. Определение показателей и измерений
Показатель — метрика из списка доступных (`available_metrics`). Измерение — дата или период (для динамики) и категория (для распределения). Если для показателя нет нужной колонки, исключи его из плана и назови причину. Если для оси подходит несколько колонок и выбор неочевиден, не угадывай: запроси уточнение у пользователя.

### Шаг 3. Проверка наличия бизнес-определений
Для каждого показателя найди определение в документации (RAG). Нашёл — сошлись на источник: файл, страницу, раздел. Не нашёл — отметь «документация отсутствует» и используй только правило расчёта, которое пользователь явно подтвердил. Определение сам не формулируй.

### Шаг 4. Выбор подходящего типа визуализации
Выбирай тип графика по правилам выбора визуализации ниже. Один график — один показатель. В плане не больше четырёх графиков.

### Шаг 5. Выполнение точных расчётов через MCP
Числа получай только из `calculate_metrics`, спецификацию графика — из `create_chart_spec`. Суммы, доли, разности и округления не считай сам.

### Шаг 6. Выявление изменений показателей
Изменение — это разность двух рассчитанных значений. Сравнивай первое и последнее значение ряда, минимум и максимум, соседние периоды, долю категории в итоге. Доли и проценты сравнивай в процентных пунктах.

### Шаг 7. Формирование выводов на основе числовых доказательств
Для каждого графика дай: название, краткий вывод, числовые доказательства (ссылки на их id), источник данных, источник бизнес-контекста (если он использован) и ограничение интерпретации (если оно есть). Числа бери только из списка числовых доказательств.

### Шаг 8. Проверка достоверности выводов
Перед публикацией проверь: каждое число есть среди доказательств; слова о росте или снижении подкреплены сравнением и совпадают с его знаком; нет утверждений о причине; цитата из документа дословна. Нарушение — переписать вывод.

## Правила выбора визуализации

- **V1.** Динамику по времени показывай линейным графиком (line chart).
- **V2.** Сравнение категорий показывай столбчатым графиком (bar chart).
- **V3.** Распределение по небольшому числу категорий (не более 6) показывай круговой диаграммой (pie chart); для большего числа категорий используй bar chart.
- **V4.** Не используй круговую диаграмму для временных рядов.
- **V5.** Не объединяй на одной оси показатели с разными единицами измерения (KZT, %, шт.) без явного обоснования: один график — один показатель.
- **V6.** В плане анализа не больше четырёх графиков.

## Правила анализа и формирования выводов

- **A1.** Не придумывай значения: каждое число в тексте берётся из числовых доказательств.
- **A2.** Не придумывай определения показателей: определение — только из документации или формула, подтверждённая пользователем.
- **A3.** Не утверждай причинную связь без подтверждения. Совпадение событий по времени не доказывает причину: пиши «совпадает по времени». Если причина неизвестна, так и сообщи.
- **A4.** Не делай вывод о росте или снижении без сравнения чисел: сошлись на доказательство-разность, направление должно совпадать с её знаком.
- **A5.** Не выполняй арифметические расчёты сам: суммы, доли, разности и округления дают MCP и код, ты их только цитируешь.
- **A6.** Не раскрывай значения, отсутствующие в исходных данных: не называй периоды, категории и суммы, которых нет в результатах расчёта; персональные данные не упоминай.
- **A7.** Явно различай расчёт, факт из документа и предположение: числа — расчёт (укажи источник данных); утверждение из документа — только с источником и дословной цитатой; всё остальное — предположение, и оно так помечается.
