# Трассировка LangSmith в DataStory AI

Приложение отправляет в [LangSmith](https://smith.langchain.com) трассы: LangGraph-воркфлоу анализа и чата, вызовы LLM, поиск в базе знаний (RAG), генерацию плана анализа и выводов, MCP-вызовы. Трассировка **выключена по умолчанию** и включается только при наличии ключа: без ключа приложение не имитирует интеграцию, а прямо сообщает, что трассы не отправляются.

## Какие переменные нужны

Все настройки читаются из переменных окружения (или из файла `.env`; переменная окружения приоритетнее).

| Переменная | Обязательна | Значение |
|---|---|---|
| `LANGSMITH_TRACING` | да | `true` — включить трассировку |
| `LANGSMITH_API_KEY` | да | ключ API из LangSmith (Settings → API Keys) |
| `LANGSMITH_PROJECT` | нет | проект для трасс, по умолчанию `datastory-ai` |
| `LANGSMITH_ENDPOINT` | нет | по умолчанию `https://api.smith.langchain.com`; для EU — `https://eu.api.smith.langchain.com` |
| `LANGSMITH_WORKSPACE_ID` | нет | нужен, только если ключ привязан к нескольким рабочим пространствам |

Правила включения:

- `LANGSMITH_TRACING=true` **и** `LANGSMITH_API_KEY` заданы → трассировка включена.
- `LANGSMITH_TRACING=true`, но ключа нет → трассировка **не** включается: в лог пишется предупреждение, на главной странице приложения показывается «LangSmith: Нет ключа» с пояснением, скрипт демо-сценария завершается с кодом 2.
- иначе трассировка выключена, лишних сетевых запросов нет.

Пример `.env`:

```dotenv
OPENAI_API_KEY=sk-...
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_pt_...
LANGSMITH_PROJECT=datastory-ai
```

## Как запустить приложение с трассировкой

```bash
pip install -r requirements.txt
cp .env.example .env            # впишите OPENAI_API_KEY, LANGSMITH_TRACING=true и LANGSMITH_API_KEY
streamlit run app.py
```

На главной странице карточка «LangSmith» должна показывать **«Включена»** и имя проекта. Дальше работайте как обычно: загрузка данных → план анализа → «Построить аналитику» → вопросы в чате. Каждый запуск графа создаёт трассу в проекте.

## Где увидеть trace

1. Откройте <https://smith.langchain.com> → **Tracing** (Projects) → проект `LANGSMITH_PROJECT`.
2. Корневые трассы называются по действию:

   | Корневой run | Когда создаётся |
   |---|---|
   | `datastory.analysis.plan` | кнопка запуска анализа: определение показателей, RAG, план, пауза на подтверждение |
   | `datastory.analysis.approve` | «Построить аналитику»: MCP-расчёты, выводы, проверка, дашборд |
   | `datastory.chat.ask` | вопрос в чате |
   | `vision.recognize_table` | распознавание таблицы на изображении |

3. Все трассы одной сессии анализа имеют одинаковое метаданное `thread_id` — найдите их фильтром по метаданным (`metadata_key = thread_id`) или откройте вкладку **Threads**.
4. Внутри трассы:

   | Span | Что показывает |
   |---|---|
   | `analyze_intent`, `retrieve_context`, `build_analysis_plan`, `validate_analysis_plan`, `human_approval`, `execute_analytics`, `generate_insights`, `verify_insights`, `prepare_dashboard` | узлы LangGraph |
   | `analysis_plan.generate` | генерация плана: цель, выбранные анализы, кто составил план (`llm`/`rules`), шаги |
   | `llm.PlanDraft`, `llm.InsightDraft`, `llm.IntentDraft`, `llm.QuestionPlan`, `llm.ChatAnswerDraft` | вызовы LLM (промпт, структурный ответ, токены, задержка) |
   | `insight.generate`, `insight.verify` | вывод по каждому графику и его проверка достоверности (нарушения, попытка) |
   | `rag.search_business_context`, `rag.search_dataset_metadata`, `rag.resolve_column` | поиск в базе знаний (тип **retriever**: найденные фрагменты с источниками и оценками) |
   | `openai.embeddings` | запрос эмбеддингов (число текстов; сами тексты не отправляются) |
   | `mcp.profile_dataset`, `mcp.calculate_metrics`, `mcp.create_chart_spec` | MCP-вызовы (тип **tool**) |

   У каждого `mcp.*` span-а: название инструмента (`mcp.tool`), длительность (`mcp.duration_ms` и штатная задержка run-а), статус (`mcp.status` = `success` / `error`, при ошибке ещё `mcp.error_type` и сообщение в поле error).

   **Красный статус у `human_approval`** с текстом `GraphInterrupt` — не сбой: так LangGraph записывает паузу на подтверждение плана пользователем.

### Что попадает в трассы

Отправляются: промпты и ответы LLM (сводка набора данных без значений строк и без персональных данных, агрегированные числа, найденные фрагменты документов), запрос пользователя в поле цели и в чате, сводки MCP-вызовов (метрика, группировка, число групп). **Не отправляются:** строки таблицы, изображения (вызов Vision исключён из трассировки, остаётся только span с именем файла и размером), тексты для эмбеддингов. Если фрагменты документов или вопросы конфиденциальны, скройте входы и выходы: `LANGSMITH_HIDE_INPUTS=true` и `LANGSMITH_HIDE_OUTPUTS=true`.

## Demo scenario: sales_2026.xlsx

Файл `data/demo/sales_2026.xlsx` — синтетические продажи вымышленной сети (январь — июнь 2026; регион × канал × категория, колонки `Month`, `Region`, `Channel`, `Category`, `Orders`, `Cancelled_Orders`, `Revenue_KZT`). В апреле выручка Astana заметно падает; причины в данных нет, и система должна так и сказать. Определения показателей лежат в `data/demo/sales_docs/*.pdf` (их можно приложить как PDF). Воспроизвести файлы: `python scripts/generate_sales_demo.py`.

Вопрос: **«Покажи динамику выручки по месяцам, сравни регионы и найди основные изменения»**.

### Вариант 1: скриптом, с автоматической проверкой в LangSmith

```bash
python scripts/run_sales_scenario.py
```

Скрипт выполняет настоящий сценарий (OpenAI, MCP, RAG): план → подтверждение → выводы → вопрос в чате, затем **через API LangSmith** находит корневые трассы сессии по `thread_id` и печатает дерево span-ов и ссылки на трассы. Коды возврата: `0` — трассы найдены в LangSmith; `1` — трассы не появились за 60 с; `2` — трассировка не включена (нет `LANGSMITH_TRACING=true` или ключа); `3` — не задан `OPENAI_API_KEY` или нет файла продаж.

### Вариант 2: в интерфейсе

1. `streamlit run app.py`, страница «Анализ данных».
2. Загрузите `data/demo/sales_2026.xlsx`.
3. В поле «Что вы хотите узнать из этих данных?» введите вопрос выше, нажмите «Составить план анализа».
4. Проверьте карточки плана (динамика выручки, сравнение по регионам), нажмите «Построить аналитику».
5. Задайте в чате «Какие изменения заслуживают внимания?».
6. В LangSmith откройте проект: три корневые трассы (`datastory.analysis.plan`, `datastory.analysis.approve`, `datastory.chat.ask`) с одним `thread_id`.

Для наборов без колонок платёжной системы (как `sales_2026.xlsx`) план строится по запросу: показатель, группировка и фильтры выбираются по вашей формулировке и проверяются по данным (см. README, «Наборы без колонок платёжной системы»).

## Диагностика

| Симптом | Причина |
|---|---|
| Карточка «LangSmith: Нет ключа» | `LANGSMITH_TRACING=true`, но `LANGSMITH_API_KEY` пуст |
| Карточка «LangSmith: Выключена» | `LANGSMITH_TRACING` не равно `true` |
| Трасс нет, приложение работает | проверьте проект (`LANGSMITH_PROJECT`), регион (`LANGSMITH_ENDPOINT`) и рабочее пространство (`LANGSMITH_WORKSPACE_ID`); трассы отправляются в фоне, после завершения скрипта подождите несколько секунд |
| В логе `403`/`401` от LangSmith | неверный ключ или регион |
| Тесты | автотесты трассировки проверяют отправку span-ов клиентом-рекордером в памяти (`tests/test_tracing.py`) и всегда выключают облачную трассировку; доставку в облако проверяет только `scripts/run_sales_scenario.py` |
